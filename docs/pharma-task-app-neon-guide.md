# Pharma Work Allocation App — Build Guide (No Docker, Neon Cloud DB)

Same stack as before — Node.js, NestJS, Prisma, PostgreSQL, React Native (Expo), Electron.
Only change: **Postgres now runs on Neon (cloud)** instead of Docker, so you never install or run a local database.

To keep this "easy, not too many tools," a few optional items from the original plan (Socket.io, refresh tokens, Turborepo) are marked **skip for now** — add them later only if you actually need them.

## Phase 1 — Neon Setup + Backend Basics (Est. 1 week) [CORE]

### Step 1: Create your Neon project
1. Go to [neon.tech](https://neon.tech) → sign up → **New Project**
2. Name it e.g. `pharma-dev`
3. Neon gives you a connection string that looks like:
```
postgresql://<user>:<password>@<endpoint>.neon.tech/<dbname>?sslmode=require
```
4. Copy it — you'll paste it into `.env` in Step 3.

Neon replaces `docker run postgres` entirely — no local Postgres process, no container to manage. Each project can also have multiple **branches** (like Git branches, but for your database) which is handy later for testing migrations safely.

### Step 2: Create the NestJS project
```bash
npm i -g @nestjs/cli
cd pharma-task-app
nest new backend
cd backend
```

### Step 3: Install and configure Prisma
```bash
npm install prisma --save-dev
npm install @prisma/client
npx prisma init
```
In `backend/.env`:
```
DATABASE_URL="postgresql://<user>:<password>@<endpoint>.neon.tech/pharma_dev?sslmode=require"
```

### Step 4: Define your schema
`backend/prisma/schema.prisma`:
```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        String   @id @default(uuid())
  name      String
  email     String   @unique
  password  String
  role      Role     @default(EMPLOYEE)
  tasks     Task[]   @relation("AssignedTasks")
  createdAt DateTime @default(now())
}

enum Role {
  MANAGER
  EMPLOYEE
}

model Task {
  id           String     @id @default(uuid())
  title        String
  description  String?
  status       TaskStatus @default(PENDING)
  assignedTo   User?      @relation("AssignedTasks", fields: [assignedToId], references: [id])
  assignedToId String?
  createdAt    DateTime   @default(now())
}

enum TaskStatus {
  PENDING
  IN_PROGRESS
  COMPLETED
}
```

### Step 5: Run the migration against Neon
```bash
npx prisma migrate dev --name init
```
This runs directly against your cloud database — no extra setup needed. Open **Prisma Studio** anytime to check data visually:
```bash
npx prisma studio
```

### Step 6: Generate the tasks module
```bash
nest generate module tasks
nest generate controller tasks
nest generate service tasks
```

### Step 7: Build the endpoints
`tasks.service.ts` → `createTask()`, `getAllTasks()`, `updateTaskStatus()`
`tasks.controller.ts` → `POST /tasks`, `GET /tasks`, `PATCH /tasks/:id`

### Step 8: Test it
```bash
npm run start:dev
```
Hit endpoints with Postman.

**Done when:** you can create/list/update tasks purely via API, backed by Neon.

## Phase 2 — Authentication & Roles (Est. 3–4 days) [CORE]

```bash
npm install @nestjs/jwt @nestjs/passport passport passport-jwt bcrypt
npm install -D @types/passport-jwt @types/bcrypt
```

- Hash passwords: `bcrypt.hash(password, 10)` on signup
- `POST /auth/login` → look up by email → `bcrypt.compare()` → sign JWT `{ userId, role }`
- Guard routes:
```bash
nest generate guard auth/jwt-auth
```
- `@UseGuards(JwtAuthGuard)` on protected routes, `RolesGuard` for manager-only routes

**Skip for now:** refresh tokens — a JWT with a few hours' expiry is enough for MVP.

**Done when:** login returns a JWT, task creation blocked for non-managers.

## Phase 3 — React Native App, Android (Est. 1.5–2 weeks) [CORE]

```bash
cd pharma-task-app
npx create-expo-app mobile
cd mobile
npx expo install @react-navigation/native @react-navigation/native-stack
npx expo install react-native-screens react-native-safe-area-context
npm install axios
npm install @react-native-async-storage/async-storage
```

Build screens in this order:
1. `LoginScreen.tsx` → calls `POST /auth/login` → stores JWT in AsyncStorage
2. `TaskListScreen.tsx` → calls `GET /tasks`
3. `TaskDetailScreen.tsx` → Accept / Complete buttons
4. `CreateTaskScreen.tsx` (manager only) → `POST /tasks`

`mobile/src/api/client.ts`:
```ts
import axios from 'axios';
import AsyncStorage from '@react-native-async-storage/async-storage';

const api = axios.create({ baseURL: 'http://YOUR_LOCAL_IP:3000' });

api.interceptors.request.use(async (config) => {
  const token = await AsyncStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

export default api;
```

Run:
```bash
npx expo start
```

**Done when:** manager creates/assigns a task, employee sees/accepts/completes it — on a real device.

## Phase 4 — Multi-Tenancy with Neon (Est. 1–1.5 weeks) [CORE]

This is the one part that changes the most without Docker — instead of running `CREATE DATABASE` on a local Postgres, you create a **new Neon project (or branch) per company** via Neon's API, or simply provision new **databases inside one Neon project** (simplest option — recommended for MVP).

### Simplest approach: one Neon project, one database per tenant

### Step 1: Control-plane schema
`backend/control-plane/prisma/schema.prisma`:
```prisma
model Company {
  id        String   @id @default(uuid())
  name      String
  companyId String   @unique
  dbUrl     String
  plan      String   @default("basic")
  createdAt DateTime @default(now())
}
```
Give it its own `.env` var: `CONTROL_PLANE_DATABASE_URL` (a separate Neon database, e.g. `pharma_control`).

### Step 2: Provisioning script
`backend/control-plane/provision-tenant.ts` — instead of local `psql "CREATE DATABASE"`, connect to your Neon project with the `pg` client and run `CREATE DATABASE tenant_<companyId>`, then apply migrations against it:
```bash
DATABASE_URL="postgresql://<user>:<password>@<endpoint>.neon.tech/tenant_acme123?sslmode=require" npx prisma migrate deploy
```
Wrap this so it runs automatically when a company signs up.

> Tip: Neon lets you create databases from its dashboard too, so early on you can even do this step manually per client while testing — no code required until you have real signups.

### Step 3: Tenant resolution endpoint
`POST /auth/resolve-tenant` → input `companyId` → look up in control-plane DB → return which tenant `dbUrl` to use internally.

### Step 4: Tenant-aware Prisma client cache
`backend/src/tenants/tenant-client.ts`:
```ts
const clientCache = new Map<string, PrismaClient>();

function getTenantClient(dbUrl: string): PrismaClient {
  if (!clientCache.has(dbUrl)) {
    clientCache.set(dbUrl, new PrismaClient({ datasources: { db: { url: dbUrl } } }));
  }
  return clientCache.get(dbUrl)!;
}
```

### Step 5: Update login flow
User submits `companyId` + email + password → resolve tenant → look up user in tenant DB → verify → JWT includes `tenantId`, `userId`, `role`.

### Step 6: Mobile app
Add a "Company ID" field to the login screen.

**Done when:** two test companies work simultaneously, tasks never cross over.

## Phase 6 — Pharma-Specific Hardening (Est. 1 week)

- **Audit log** [CORE] — `TaskEvent` model (id, taskId, action, actorId, timestamp), append-only
- **Real-time updates** — **skip for now**; a manual refresh button is fine for v1
- **Per-company data export** [CORE] — endpoint dumping a company's tasks/events as JSON/CSV
- **TLS** [CORE before go-live] — Neon connections are already encrypted (`sslmode=require`); you still need HTTPS in front of your NestJS API itself (Caddy or Nginx, or your hosting provider's built-in TLS if using something like Render/Railway/Fly.io)
- **Compliance review** [CORE if targeting GxP/21 CFR Part 11] — sit down with the client's QA team before finalizing e-signature/retention behavior

## Quick Reference — What Changed From the Docker Version

| Item | Before | Now |
|---|---|---|
| Local Postgres install | Docker container | **Removed — Neon cloud DB** |
| `DATABASE_URL` | `localhost:5432` | Neon connection string (`sslmode=require`) |
| New tenant DB creation | `psql -c "CREATE DATABASE ..."` locally | `CREATE DATABASE` against Neon (via `pg` client or Neon dashboard) |
| Everything else (NestJS, Prisma, React Native, Electron, JWT auth) | Same | Same |
